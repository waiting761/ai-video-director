# 即梦（Seedance）：让造型动起来

即梦的页面常改，下面是 2026 年 11 月实测时的样子。按钮名对不上时先截图看清再点，不要凭坐标盲点。

## 边界

- 需要会员。我们试过免费账号：视频生成的所有模型（Seedance 2.0 mini 到 2.5）和 720P 都带会员标，提交时弹“升级会员即可解锁”，免费积分花不出去。
- 只用账号持有人本人在浏览器里已登录的账号，经浏览器扩展操作；不代为登录，不切账号，遇到验证码或风控提示就停下告诉持有人。
- 带图生成时可能会弹“安全确认”（精卫那次没有弹，应龙第一条提交也没有弹），要声明图片是本人的或已获授权。这是替账号持有人签的声明，一律由账号持有人本人点，助手不代点。再弹出时同样处理。
- 即梦只用来出视频。造型稿和关键帧仍用 Codex 出：Codex 在订阅里，即梦的图片生成我们试过，觉得很一般。
- 不去水印。发表时一定要打平台上的 AI 声明。
- 即梦首页有“即梦 CLI”，那是要装的命令行工具，我们只用网页。

## 价目

各档的价钱和该用在哪里，见 `routes.md` 的工具表。表里的原价是从页面上划掉的数字读出来的，开工前在页面上再看一眼，第一笔扣费以后核实。时长可以拉到 4 到 15 秒，积分按秒涨。生成一条 5 秒要等三到五分钟，可以同时排好几条。2.5 有一个 480P 的样片模式，只能出样片，升正片只能选 1080P 或 4K。

## 和 Veo 比（帝江高潮那一镜）

同一组首尾帧、同一段提示词，提示词按秒写动作：“0 到 1.5 秒只有云涡在转；1.5 到 4 秒扉棱缓慢张开，最多到约 35 度就停住；4 到 5 秒扉棱不动，云越转越快”。Veo 在 3.5 秒就把扉棱张到水平，读成机械螃蟹；即梦两档都停在要的角度，身体不离山峰，云涡比 Veo 足。2.5 的动作幅度和细节略好，Fast VIP 的扉棱张得小一些、红光亮得早。所以在首尾帧模式下，这一镜上按秒写动作管用；全能参考下管不管用，我们没有试过。只有一镜，别当成规律：帝江另一镜写了按秒呼吸，Fast VIP 和 2.5 都几乎不演。

## 挂图

视频生成页的输入框默认是“全能参考”模式：挂上参考图，让 Seedance 自己出动作和运镜。要锁住一个镜头的开头和结尾（闭眼到睁眼这类状态变化，或者要接上一镜），点输入框下方的“全能参考”，在下拉里换成“首尾帧”，首帧、尾帧两个框才会出来；每次重新打开页面都要换一次。只挂首帧、不挂尾帧也能提交，价钱一样。

我们走通的路线是“首尾帧模式只挂首帧”。精卫那一期试过：mini 档在全能参考里挂白底设定图，开头一秒半漏出设定图的灰色背景；同一提示词、同一参考图在 Fast VIP 上第 0 秒就有场景，所以不能说全能参考一定漏背景，我们没有做完整对照（`cases/jingwei-v1.md`）。带场景的关键帧当首帧、只挂首帧，是我们走通的做法，也是我们推荐的默认。全能参考的输入框里有一句提示：“例如：@图片1 模仿 @视频1 的动作，音色参考 @音频1。”看样子它能同时挂图片、视频和音频当参考；拿一段参考视频带动作，我们没有试过。

### 用浏览器扩展挂首尾帧的脚本

这一小节只在用浏览器自动化工具操作时才需要；人自己在页面上点上传就行，不需要脚本。动手前先读一遍网站的服务条款，确认它允许自动化操作。脚本改写的是页面里的浏览器函数，网站改版后可能失效，用完要让页面恢复原样（刷新页面即可）。

即梦的首帧、尾帧框用的是浏览器的 `showOpenFilePicker`，页面上没有文件框，扩展的上传工具找不到。先在页面里执行这段，造一个自己的文件框，并让即梦从它取图：

```js
let inp = document.getElementById('jm-my-input');
if (!inp) {
  inp = document.createElement('input'); inp.type = 'file'; inp.id = 'jm-my-input';
  inp.setAttribute('aria-label', 'jm-my-input');
  inp.style.cssText = 'position:fixed;left:0;bottom:0;width:120px;height:30px;z-index:999999';
  document.body.appendChild(inp);
}
window.showOpenFilePicker = async () => {
  const f = document.getElementById('jm-my-input').files[0];
  if (!f) throw new DOMException('aborted', 'AbortError');
  return [{ kind: 'file', name: f.name, getFile: async () => f,
            queryPermission: async () => 'granted', requestPermission: async () => 'granted' }];
};
```

即梦页面的视口高度会变（九尾狐那一期中途从 779 变成 728，首帧槽、提交按钮都往上挪了约 50 像素），每次挂图以前先截一张图核对位置，不沿用旧坐标。然后每张图两步：用浏览器扩展的 find 找 “jm-my-input”，用 file_upload 把图传进这个框；再点首帧（或尾帧）框，即梦就会挂上这张图。挂完放大截图看一眼首尾帧缩略图对不对。文件框别放在页面中间，会挡住视频上的下载按钮。

提交前核对提示词没有被手打错：精卫那一期往输入框里打提示词时，“湿漉漉”被打成了“湿淋淋”，看截图没看出来，是回显的文字里发现的。从此每条提示词提交以前，用输入框里读回来的文字和提示词文件比哈希，一致才提交。

## 写提示词

中文写就行。写清导演意图、镜头怎么动、主体做一件什么事；用了首尾帧的，开头写“首帧到尾帧”。用首尾帧时，要精确控制的动作按秒写，写到“最多到多少度就停住”“保持不动”，即梦在帝江高潮那一镜上听了，动作停住了；帝江另一镜写了按秒呼吸却几乎不演，所以不是每次都灵。要排除的东西放在最后写（没有别的生物，没有文字和字幕；故事里没有人的，再写没有人）。凤皇的起舞那一镜写的是“0 到 5 秒慢慢展翅，5 到 7 秒仰头张嘴”，第三版基本照着秒数走。

九尾狐那一期摸出来的几条，都是首尾帧模式下拍巨物的经验，拍奔跑、打斗和几个角色同框时只当参考：

- 即梦照首帧的颜色走，提示词里写颜色只是补充。进即梦以前，把首帧主体的色相、饱和度和定稿的关键帧量一下；首尾帧是拼出来、锁出来的，再整张比一次天空的色调，两张的天差几级，即梦就会演成整片天变色；修法是只对天空做低频的色差匹配，让尾帧往首帧靠。成片颜色不对，先用同一个变换逐帧调色，不花积分。做金属材质时，调色要留着柔和的高光，金属感靠它，抹平了就像蜡。
- 写“身体全程不动”“眼睛不眨”，出来就是雕像。要活，按秒写慢的身体动作。
- 巨物镜头里写“头往一侧转一点”，会被演成半秒内转向镜头。
- 首尾帧之间“收拢的一束散开”，九尾狐同一个镜头试了三种写法，即梦都先整片掀起来，提示词压不住。从结构上改：首帧里就让每一条各自分开，只拍从垂着到扬起来；不行再加一张中间帧，拆成两段。
- 想要俏皮，写尾巴或身体去做一件小事（尾巴扫歪斗笠），不写嘴角、斜看这类表情。眨眼写成“很快的一下”，即梦仍会闭上半秒多，读成满足地眯眼；九尾狐那一条最后接受了。
- 鸟最好不要写“看向镜头”（两样是一起改的，分不清是哪一样起的作用）：精卫第一抽按提示词先看向镜头，转成了正脸，Gemini 读成“京剧脸谱”，盲看说像换了一只鸟；第二抽把首帧左右翻转、提示词不写转身，整条五秒都是侧身。
- 写让小鸟“飞起又落回”，即梦会凭空变出鸟：颍川那一镜，一只半透明的麻雀淡入、扑腾、在半空消失。提示词只写“低头啄、跳一两步”。
- 写“云海慢慢平下来”，即梦会把云面整体降低，藏在云下的长腿就露出来，尺度塌了。要写死“云海的高度全程不变，始终淹到肚子下面”。
- 写“涟漪”，凤皇出了白色同心弧，没有记下补救写法。帝江高潮那一镜成功的写法是“每次鼓起都亮起来，波纹随亮度推出去”，那是另一镜，可以参考，不是对涟漪的补救。

一位创作者在 Seedance 上踩过的几条，他走的是云厂商的接口，即梦网页上会不会一样我们没有试过：写实人脸的参考图被拒收，他的人物只拍背影、远景，或者用手绘画风；手靠近脸会被画成手套一样，他让手出画；写“脸涨得通红”，出来是血红的脸，他改写成“肤色自然”，所以颜色词要写得平实；画面里的字和招牌会变成乱码，要出现的字一律用代码后加。参考图被拒收时，换构图或画风，不用遮挡、加标记这类办法去绕审核。

提示词可以按七段式排，每段一个小标题，逐段对着首尾帧核：画风（和首尾帧一致）、镜头（几秒、景别、机位、怎么动，不动就写不推不拉不摇）、构图与配色（主体在画面哪里，什么颜色，要和首帧对得上）、主体（神兽的长相写死）、逐秒（0 到 0.2 秒和首帧一模一样，中间每段写谁做什么、往画面哪边，最后 0.3 秒和尾帧一模一样）、声音（只有看得见来由的声音）、约束（画面里一直只有首帧里的东西，没有文字、字幕、水印）。写“不要怎么样”常常没用，能改成正面说法的就改。

## 2.5 的三个已知毛病

一位创作者记了三条，凤皇那一期碰上了第一条：

- 写了“没有音乐”，仍可能混进音乐。凤皇的起舞那一条（2.5）底下有一层乐音，剪辑时换成了云海上的风声；Fast VIP 的几条底下也出过一层嗡声（200 Hz 的整倍数），所以不只 2.5，即梦的原声都要查，画频谱看最清楚。应龙那期，提示词写了“没有音乐”，有一镜整段仍是一个有固定音高的嗡声，是 Gemini 听出来、再画频谱确认的。听不了就按有音乐处理。
- 结尾几帧可能突然跳成尾帧的样子。剪辑时逐帧看最后半秒，跳了就停在跳之前的那一帧。
- 第一帧可能特别锐。直接去掉这一帧。
- 帧率：即梦下载的 mp4 文件头标 60 fps，实际画面是 24 fps。精卫第一版按 30 fps 出片，每 2 秒 61 帧里只有 49 帧不同，推近和飞行的镜头每秒顿 6 下；之后成片都按 24 fps 出（`cases/jingwei-v1.md`）。

## 下载与出片检查

在页面里用脚本读视频地址会被扩展拦下，只能点页面上的下载按钮。点开视频进详情页，右上角的“下载”最稳；生成列表里悬停也有下载图标，但位置跟着卡片在页面上的高度变，容易点偏。720P 档下来是 1280×720；文件头写的是 60 帧，实际画面是每秒 24 帧（重复帧），剪辑时必须按 24 帧处理，按 30 帧取帧，每 2 秒 61 帧里只有 49 帧不同，推近和飞行的镜头每秒顿 6 下（精卫第一版就这样）。下载后立刻改成镜头名存好，挑的理由写进提示词记录。

每条片子下载下来就跑一遍相邻帧差，找冻住的开头和周期性的重复帧：精卫开头那一镜，一条前 31 帧一动不动，另一条在 3.58 到 4.08 秒每三帧重复一帧；这两样都是出片以后才发现的。

即梦下载的原片在文件元数据里带着 AI 标识字段；剪辑脚本重新编码，成片里这个字段没了。我们当时的处理是在发布包里写明成片没有这个字段，没有写回。建议把原片的元数据带进成片，带不进就在交片清单里写明。《人工智能生成合成内容标识办法》自 2025 年 9 月起施行，其中对元数据标识怎么要求，请自己核对现行条文；我们没有逐条对照过。平台上的 AI 声明是这条片子唯一可见的 AI 标识，发表时一定要打。

## 还没摸清的

页面上的短剧工作室：写着剧本创作、短剧画布、导演台、智能预演、片段重拍、重制转绘、超分工作流和视频拉片；左侧栏还有“主体”，看上去能存一个角色反复用。导演台写的是“排演布景，告别抽卡”，智能预演写的是“预演镜头，规划分镜”。它们都可能帮同一个角色撑过很多镜头，我们没有用过。短剧里的 Agent 是让即梦自己的代理写剧本、当导演，和这套做法由 Opus 当导演相反，所以不用。
