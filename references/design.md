# 设定集：造型、盲看与改图

后面每一个镜头的一致性，主要靠这一步。造型稿挑不好、设定图不成套，就算后面花再多积分，主角也会一镜一个样。

## 设计语言

目标是：美、让人惊艳，一眼认得出是什么，不是机器人，也不是博物馆里的雕像。《山海经》这个系列前几只都画成比山还大的巨物，这是好用的一种画法，不是每只都要。材质和气质每只按经文和故事定：烛龙到帝江是“比历史更老的青铜器”，九尾狐是活的白狐，柔和、美丽、俏皮。下面第一条是青铜这一路的做法，换材质时只取用得上的。

- 青铜这一路，材质是氧化的古青铜，带绿锈。头和脸当青铜器来设计：按这只神兽在古书里的形状，找对应的商周青铜器，人面的找三星堆面具式的大平面、长鼻梁、重眉骨、闭着的宽嘴，牛形的找牛首形器和兽面纹，抽象、几何，不像真兽也不像真人。夔可以直接用青铜器上的夔纹、龙纹去做身体的纹样。
- 一足、多首这类怪异的肢体，不正面完整地展示，埋进海里、云里或雾里，只露出一部分。夔的独足照“侧视夔纹、腿粗靠前”写了提示词，出来的还是架在细腿上的鳄鱼。头的形状（牛头这类）出图时很难一次对，留到关键帧阶段用改图来修。多首的蛇或龙，每个露出来的头都要带一段往后没进云雾的脖子，头低趴着、不立着；相柳只露脸，画出来是山顶上的三尊石像。
- 全画只留一处饱和的强调色。青铜这一路给眼睛或那个决定性的动作（夔给鼓面和声浪）；九尾狐给了大禹腰上的一条朱红腰带，白狐、淡金晨光和青灰远山都压着饱和度，那一点红就把画面撑住了；应龙是深炭灰的鳞、比亮天暗的灰翅，琥珀色的眼睛是画面里唯一饱和的颜色。
- 画巨物时，比例靠真实的风景来给：黄山的花岗岩峰和松树、云海、海面上的浪和岛。巨物从不完整露出，总有一部分埋在云里、雾里、水里，或者被画框切掉。
- 故事里本来就有人的（九尾狐的大禹），可以放一个很小的人当比例尺，人只到神兽的脚趾那么高；人要和神兽站在同一个深度，放在近景会显得比爪子还大。九尾狐那一期不出现女子、红衣美人和人形狐妖，是为了不让它被读成狐狸精，这是那一张选题单的边界；故事片里本来就有的人物（女娃、夸父、大禹）照经文来画。
- 画面是写实的电影级概念画：大气透视、一层层的雾，16:9。没有文字、标志和水印。
- 一眼认得出是这种动物。九尾狐第一轮胸口堆了一圈厚鬃毛，被说“像一条哈士奇”；改成细长口鼻、尖窄的脸、大三角耳、身上的毛长而顺，才读回狐狸。改过头，身子又细得像灵缇犬，所以每轮都问一句“这是狐狸，还是狗、狼”。

九尾狐用成了的一种构图：镜头放低到人的高度往上仰，神兽从画面上方低下头来，大到画框装不下，后半身出画；逆光，长毛的边缘透出一圈亮边，远山和云海虚掉，前景是湿的岩石。在这之前出的几轮都是神兽全身侧站、四周一大片空天，像角色设定图，零件都对也不好看。

烛龙用成了的三种构图：沿着脊背望向远方，一节节青铜拱没入雾中；夜里的山上裂开两道竖缝，过一会儿才看出那是眼睛；逆光的侧影，先读成山，再读成一张脸。正面打光把身体照亮，巨物就显小，所以优先用逆光、雾里、剪影。

## 设定集怎么出

一条片子里同一只要出现很多镜头时，靠设定集保持一致。造型稿挑定以后，用改图的写法从定稿出同一只的一组设定图，每一张都把定稿当参考图传进去：

- 多角度：正面、侧面、背面、四分之三侧，同一个光、同一个背景色，身体比例对得上。
- 局部：头和脸、脚或爪、尾巴，以及最有标志性的那一处，各出一张近景。
- 尺度：和山、云或人放在一起的一张，定下它到底有多大。
- 世界：这一条片子的光（几点钟、从哪边来）、季节、天气、色板和材质，各出一两张没有主角的环境图。

故事里有人物的（精卫填海里的女娃），人物也出一套：正面、侧面、背面和全身，服饰、发式和随身的东西按故事的年代写进共用风格段，不出现现代的东西。

人物的几条经验来自一位创作者公开的做法，他走的是云厂商的 Seedance 接口，不是即梦网页，所以在即梦上会不会一样，我们没有试过：写实人脸的参考图，在他当时用的模型和账号权限下被拒收，所以他的人物只拍背影、远景，或者干脆用手绘画风；关键帧里人物太小，脸会漂；同一段戏里的年龄、发型和服装要一致，他那条手绘画风的剧情片还是出了一镜白发、一镜黑发，是另开的一个代理通看全片才查出来的。所以写实画风的人物先按背影和远景来设计，试过即梦收不收正脸、脸漂不漂，再决定要不要拍正脸。

设定图出完，派盲看的审阅代理只看这一组图，问它们是不是同一只；不是的那一张重出。

## 盲看与改图

造型稿、设定图、关键帧和每一条视频试片，都派一个只看图或视频、不读提示词的审阅代理看一遍，叫盲看。先问开放题“这是什么”，再问这一只最怕被读成什么（是狐狸还是狗、读不读得出威胁）；关键帧再加一问，像不像某部知名作品里的东西——一位创作者的片子里，王座画得太像一部知名美剧里的那把，就是审关键帧时查出来的。九尾狐那一期的多数问题是盲看抓出来的。

- 最怕的读法在出图以前就列成一张失败名单，写进笔记，盲看读成其中一样就不过。帝江第二版被读成小鼎、飞碟，第三版先后被读成虫子、灯笼、火球、一片天空，每换一种画法就换一种坏读法。
- 观众多半在手机上看，每批盲看都加一档缩到 400 像素宽的。再把图转成黑白看一遍，主体和背景分不开，就是明暗不够，要改光（这条是一位创作者的建议，未验证）。颍川的群鸟就是在 400 像素宽的静帧上被读成了“秧苗、田垄”和“养殖场”（`cases/fenghuang.md`）。
- 判断好不好看，先看构图和光，再看零件。九尾狐连修几轮尾巴数、眼神、腿长，零件都对了画还是不好看，换成仰拍、让狐狸大到画框装不下以后才好看。
- 图像模型常自己往图里加没有依据的细节：我们碰到过技术示意图里多出没核验的名称、设备和规格文字，甚至一件毫不相干的日常物品，历史复原图里出现了后世才有的构件。提示词里把需要的对象逐项写明，加一句“只画这些，不添加其他设备、文字和口号”；出图后逐张对照事实底稿核对每个新增元素，只做一次定向修改，不整张重抽。
- 图像模型不执行像素数一类的数值约束。我们要求两支箭头“约 110 像素”，两轮都没做到（出来一个约 150、一个约 90），而图上的论点正是“大小不变”；改写成“同一根箭头镜像对称、可重叠”的几何描述，一次通过。图形关系用几何或对称来描述；一张工程示意图要求“同一刚体平移”和“留缝尺寸”，出图两次用尽仍不合格，几何要求高的画法重试一两次不收敛，就改分镜降低要求，不继续重试。
- 科普配图可能被图像接口的内容审核以“暴力”为由拦下（返回 moderation_blocked），原因没有查清，接口也没给触发细节。被拦后保留完整提示词和失败回执，改成博物馆展陈、结构剖面、无武器的写法最多再试一次，仍不行就停下来，由委托人决定换题还是改用自己画的图解；不要为了通过审核换别的接口，也不要拿占位图当完成品。
- 数目、眼神这类局部问题，在最好的那张上局部改，改完把其余像素锁回原图，不整张重抽：整张重抽每次都是重新抽签，不会收敛。
- 动作是别人拿它做的（夔的鼓），造型稿也要画那件东西，至少一张静着的、一张动作发生的那一刻，否则片子里最要紧的画面要到关键帧阶段才第一次出现。这一套图既是出镜头时挂的参考图，也是 Codex 画分镜图和首尾帧时传进去的参考。分镜图不用精致，构图、景别和光对就行，用同一份共用风格段来出，让整条片子的样子在花积分以前就看得见。
- 同一只的几张造型稿要放在一起盲看，问“这四张会不会被当成同一只”。应龙的四张造型稿，盲看说“如果这四张要在同一条片子里出现，观众很可能以为是两三条不同的龙”；第一张通体银白，被读成一只巨大的白鸟或者天使。救法是把盲看挑出来的毛病写成硬约束，再出下一组，每张都挂造型稿里最接近的那张当参考图。

## 提示词写法

一份共用风格段，加每张图一句构图。共用风格段照这个结构写：

1. 画面类型：photographic cinematic matte painting，并点名不是 illustration、game art、cartoon、museum statue。
2. 镜头与大气：extreme telephoto、aerial perspective、layered haze、16:9 1920x1080，no text、no logo、no watermark；故事里没有人的，再加 no people。
3. 世界：山、云、海、季节和色调，写成和前一只同一个世界。
4. 主体：这只神兽在古书里是什么样（一句话），它是一只兽，材质按这一只的经文和故事定（青铜不是固定的；不是一件长了腿的器物，也不是机器），有多大，脸或身体参照什么，强调色只给哪里。
5. 情绪：按这一只的气质写，九尾狐写的是 gentle、luminous、playful。系列定位改成神兽祥瑞、不是怪兽以后，不再写 terrifying。

每张构图一句，写清机位、露出哪一部分、拿什么当比例尺、光从哪来。出三四张不同的构图，比同一构图出四版更有用。

## 出图

`codex exec` 能直接出图，一张约 1 分钟。提示词要写在 `-i` 前面（`-i` 会吞掉后面的参数），后台运行时要接 `</dev/null`，否则会卡住：

```sh
codex exec -C "$PWD" -s workspace-write --skip-git-repo-check -c model_reasoning_effort="medium" \
  "Generate one image: <共用风格段> <这一张的构图>. Save the PNG into the current working directory as <名字>.png and print its absolute path." </dev/null > log-<名字>.txt 2>&1 &
```

Codex 只写启动目录，所以提示词里要要求它把图存到当前目录。改图出关键帧时，把原图用 `-i` 传进去，提示词写成“Edit the attached image. Keep every pixel of the composition identical ... Change only ...”，只改一样东西（闭眼、入夜、换季）。改完把新旧两张叠在一起看，构图有没有漂。

## 常见的坏样子

- 太阳圆盘或月亮放进画面，会变成比例尺，巨物立刻显小。
- 青铜甲板画成一块块拱起的鳞，会读成龟壳；近处一节断开，会读成沉船。
- 发光的肋节、分开的一根根柱子，会读成蘑菇或眼镜蛇。
- 脸画得太像人或太像龙，都会变丑；要像青铜面具。
- 夏天的饱和蓝天和晨昏的青铜调不在一个世界，换季要在出图时就压着饱和度写。
- 写实的毛和代码画的部件拼在一起，会读成贴上去的羽毛扇。九尾狐试过用代码画尾巴，条数保住了，毛的粗细、颜色和根部都对不上，放弃了。
- 中国上古的台写 rammed-earth platform、straight walls、layer lines、no stairs；写 stepped 会画成正中一道大台阶的玛雅金字塔。
- 圆身体的神兽（帝江）：露出一排细腿，手机尺寸上读成发光的虫子；腿埋进云里、俯视看到整个圆，读成带翅膀的火球；仰拍、身体被裁掉、边缘融进云气，又读成光和天气。详见 `cases/dijiang-v3.md`。
- 细长的飘带尾巴（精卫第一版）在视频里像两根铁丝，转到正面会消失；照古图改成宽大的长尾羽就稳了。
